## 1. Project Overview

A standalone Node.js REST API backend for a bank management system. It mirrors the contract expected by an existing Next.js frontend, implements custom JWT authentication with rotating refresh tokens, and enforces core banking rules (balance checks, atomic transfers, transaction history, notifications).

**Database:** MySQL, accessed exclusively through Sequelize ORM. Schema is synced from models on startup (`sequelize.sync()`). This is intentional for this phase — no migration files are used.

All database access is mediated through a repository layer — services never call Sequelize directly. See Section 5 for the full repository pattern specification.

**Key constraints:**
- No overdraft allowed under any circumstance
- Transfers only between accounts of the same currency
- One account per user, auto-created at user creation
- `bankUserId` is the user's permanent login ID (8 digits) — auto-generated by the bank at creation, sent to the user, immutable, and not the DB `id`
- `accountNumber` is 14 digits, auto-generated, unique
- Roles: `admin`, `employee`, `user` — no other roles exist
- All monetary values stored as `DECIMAL(15,2)` — no floats, no integers-as-cents
- All FK constraints use `ON DELETE RESTRICT` — the application layer must clean up dependents before deleting a parent record
- Primary keys are `INTEGER AUTO_INCREMENT` on all tables

## 5. Repository Pattern

### 5.1 Purpose

The repository layer is the **only** place Sequelize models are imported and called. No service, controller, route, validator, or utility file may import a Sequelize model or call Sequelize methods directly. Violations of this rule are bugs, not style issues.

### 5.2 BaseRepository

`src/repositories/BaseRepository.js` provides shared methods used by all repositories:

```js
class BaseRepository {
  constructor(model) {
    this.model = model;
  }

  async findById(id, options = {})
  async findOne(where, options = {})
  async findAll(where = {}, options = {})
  async create(data, options = {})
  async update(where, data, options = {})
  async delete(where, options = {})
  async count(where = {})
  async findAndCountAll(where = {}, options = {})  // used for pagination

  // SQL transaction wrapper — all banking operations use this
  async withTransaction(callback)
  // callback receives a Sequelize transaction object `t`
  // usage: await this.withTransaction(async (t) => { ... })
  // if callback throws, the transaction is automatically rolled back
  // isolation level is SERIALIZABLE for all withTransaction calls
}
```

### 5.3 Repository Singletons

Each repository is instantiated once and exported as a singleton:

```js
// src/repositories/UserRepository.js
const BaseRepository = require('./BaseRepository');
const User = require('../models/User.model');

class UserRepository extends BaseRepository {
  constructor() { super(User); }

  async findByBankUserId(bankUserId)
  async findByEmail(email)
  async findByNationalIdHash(hash)
  async incrementFailedAttempts(id)       // UPDATE users SET failedLoginAttempts = failedLoginAttempts + 1 WHERE id = ?
  async resetLoginAttempts(id)            // UPDATE users SET failedLoginAttempts = 0, lockoutUntil = NULL WHERE id = ?
  async lockUser(id, lockoutUntil)        // UPDATE users SET lockoutUntil = ? WHERE id = ?
  async setMustChangePassword(id, value)  // UPDATE users SET mustChangePassword = ? WHERE id = ?
  async searchUsers(filters, pagination)  // name, email, bankUserId, role filters + page/limit
}

module.exports = new UserRepository();
```

```js
// src/repositories/AccountRepository.js
class AccountRepository extends BaseRepository {
  constructor() { super(Account); }

  async findByUserId(userId)
  async findByAccountNumberHash(hash)
  async creditBalance(accountId, amount, transaction)   // UPDATE accounts SET balance = balance + ? WHERE id = ?
  async debitBalance(accountId, amount, transaction)    // UPDATE accounts SET balance = balance - ? WHERE id = ?
}
module.exports = new AccountRepository();
```

```js
// src/repositories/TransactionRepository.js
class TransactionRepository extends BaseRepository {
  constructor() { super(Transaction); }

  async findByAccountId(accountId, filters, pagination)
  // filters: type, startDate, endDate, minAmount, maxAmount
  // pagination: page, limit
}
module.exports = new TransactionRepository();
```

```js
// src/repositories/RefreshTokenRepository.js
class RefreshTokenRepository extends BaseRepository {
  constructor() { super(RefreshToken); }

  async findByTokenHash(hash)
  async revokeToken(id)                        // UPDATE SET isRevoked = true WHERE id = ?
  async revokeFamilyByUserId(userId, family)   // UPDATE SET isRevoked = true WHERE userId = ? AND family = ?
  async deleteExpired()                        // DELETE WHERE expiresAt < NOW()
}
module.exports = new RefreshTokenRepository();
```

All other repositories (Notification, AuditEvent, ContactMessage) extend BaseRepository with no additional methods beyond `create` and `findAll`.

### 5.4 Passing Transactions

When `withTransaction` is used, the Sequelize transaction object `t` must be passed to every repository call inside the callback via the `options` parameter:

```js
await baseRepo.withTransaction(async (t) => {
  await AccountRepository.debitBalance(fromId, amount, t);
  await AccountRepository.creditBalance(toId, amount, t);
  await TransactionRepository.create({ ... }, { transaction: t });
});
```

If the transaction object is not passed, Sequelize will execute the query outside the transaction silently. This is a bug. Every repository method that participates in a banking operation must accept and forward the `options` parameter to Sequelize.

## 6. Database Design

### 6.1 Sequelize Sync Configuration

In `src/config/db.js`:

```js
const { Sequelize } = require('sequelize');
const config = require('./index');

const sequelize = new Sequelize(config.DB_NAME, config.DB_USER, config.DB_PASSWORD, {
  host: config.DB_HOST,
  port: config.DB_PORT,
  dialect: 'mysql',
  logging: config.NODE_ENV === 'development' ? console.log : false,
  pool: { max: 10, min: 0, acquire: 30000, idle: 10000 },
  dialectOptions: {
    decimalNumbers: true   // return DECIMAL columns as JS numbers, not strings
  }
});

async function connectDB() {
  await sequelize.authenticate();
  await sequelize.sync({ force: false, alter: false });
  // force: false — never drop tables
  // alter: false — never auto-alter columns; schema is defined in models only
}

module.exports = { sequelize, connectDB };
```

`sequelize.sync()` is called once at server startup. It creates tables that do not exist. It does **not** alter or drop existing tables. If a model changes, the developer must manually apply the change to the DB during development.

### 6.2 Users Table

```js
// src/models/User.model.js
{
  id:                    INTEGER, AUTO_INCREMENT, PRIMARY KEY
  bankUserId:            VARCHAR(8),  UNIQUE, NOT NULL        // 8-digit numeric string, immutable
  name:                  VARCHAR(255), NOT NULL
  email:                 VARCHAR(255), UNIQUE, NOT NULL
  passwordHash:          TEXT, NOT NULL                       // argon2id hash
  role:                  ENUM('admin','employee','user'), NOT NULL
  nationalIdEncrypted:   TEXT, NULL                           // AES-GCM encrypted
  nationalIdHash:        VARCHAR(64), UNIQUE, NULL            // HMAC-SHA256, for lookup
  phoneEncrypted:        TEXT, NULL                           // AES-GCM encrypted
  phoneHash:             VARCHAR(64), NULL                    // HMAC-SHA256, for lookup
  dateOfBirth:           DATEONLY, NULL
  gender:                ENUM('male','female'), NULL
  departmentName:        VARCHAR(255), NULL                   // employees only
  departmentRegion:      VARCHAR(255), NULL                   // employees only
  departmentRole:        ENUM('admin','employee'), NULL       // employees only
  departmentSince:       DATE, NULL                           // auto-set to createdAt on employee creation
  departmentStatus:      ENUM('active','inactive'), NULL      // auto-set to 'active' on employee creation
  mustChangePassword:    BOOLEAN, NOT NULL, DEFAULT false     // true for all new users until first password change
  isActive:              BOOLEAN, NOT NULL, DEFAULT true
  failedLoginAttempts:   INTEGER, NOT NULL, DEFAULT 0
  lockoutUntil:          DATE, NULL
  createdBy:             INTEGER, NULL, FK → users(id) ON DELETE SET NULL
  createdAt:             DATETIME
  updatedAt:             DATETIME
}
```

**Indexes:**
- `bankUserId` — UNIQUE
- `email` — UNIQUE
- `nationalIdHash` — UNIQUE (nullable — MySQL allows multiple NULL in unique index)
- `phoneHash` — INDEX (not unique — multiple users may share a phone in edge cases)
- `role` — INDEX (for filtering in management queries)

**Indexes:**
- `tokenHash` — UNIQUE

### 6.9 Sequelize Associations

## 7. Authentication & Authorization

### 7.1 Token Strategy

| Token | Expiry | Storage | Transport |
|---|---|---|---|
| Access token (JWT) | 10 minutes | Frontend memory only | `Authorization: Bearer <token>` header |
| Refresh token (JWT) | 30 days | HTTP-only cookie + MySQL `refresh_tokens` table | `Set-Cookie: refreshToken=...; HttpOnly; Secure; SameSite=Strict` |

### 7.2 Login Flow

1. Client sends `{ bankUserId, password }` to `POST /api/v1/auth/login`
2. `UserRepository.findByBankUserId(bankUserId)` — return `INVALID_CREDENTIALS` (401) if not found (do not leak whether the user exists)
3. Check `isActive` — return `ACCOUNT_INACTIVE` (400) if false
4. Check `lockoutUntil` — if `lockoutUntil > now`, return `ACCOUNT_LOCKED` (401) with remaining seconds
5. Verify password with `argon2.verify(user.passwordHash, password)`:
   - On failure: call `UserRepository.incrementFailedAttempts(id)`; if `failedLoginAttempts + 1 >= 5`, call `UserRepository.lockUser(id, now + 15min)`; return `INVALID_CREDENTIALS` (401)
   - On success: call `UserRepository.resetLoginAttempts(id)`
6. Generate access token (JWT, 10m, payload: `{ sub: user.id, role: user.role, bankUserId: user.bankUserId, mustChangePassword: user.mustChangePassword }`)
7. Generate refresh token (JWT, 30d), assign a new `family` UUID (`crypto.randomUUID()`)
8. Hash refresh token with SHA-256 via `tokenHelpers.hashToken(rawToken)`
9. Call `RefreshTokenRepository.create({ userId, tokenHash, family, expiresAt: now + 30d })`
10. Return access token in response body; set refresh token as HTTP-only cookie via `res.cookie('refreshToken', rawToken, { httpOnly: true, secure: NODE_ENV === 'production', sameSite: 'strict', expires: expiresAt })`
11. Call `AuditEventRepository.create({ actorId: user.id, actorRole: user.role, action: 'LOGIN', targetId: user.id, targetType: 'User', ipAddress: req.ip })`

**`mustChangePassword` enforcement:**
- `mustChangePassword: true` is set on all new users created by admin/employee
- After successful login with `mustChangePassword: true`, tokens are issued normally
- The `authenticate` middleware reads `mustChangePassword` from the decoded JWT payload
- If `mustChangePassword === true`, every protected route except `PATCH /api/v1/profile/password` must return `403 MUST_CHANGE_PASSWORD` immediately — the route handler is never reached
- After a successful `PATCH /api/v1/profile/password`, call `UserRepository.setMustChangePassword(id, false)`

**Success response:**
```json
{
  "success": true,
  "data": {
    "accessToken": "<jwt>",
    "mustChangePassword": true,
    "user": {
      "id": 1,
      "bankUserId": "30000001",
      "name": "Mohamed Ibrahim",
      "role": "user",
      "email": "user@example.com"
    }
  }
}
```

### 7.3 Refresh Flow

1. Client sends `POST /api/v1/auth/refresh` — browser sends cookie automatically
2. Extract raw refresh token from `req.cookies.refreshToken` — return `TOKEN_INVALID` (401) if absent
3. Verify JWT signature and expiry via `tokenHelpers.verifyRefreshToken(raw)` — return `TOKEN_EXPIRED` or `TOKEN_INVALID` accordingly
4. Hash the raw token: `hash = tokenHelpers.hashToken(raw)`
5. Call `RefreshTokenRepository.findByTokenHash(hash)` — return `TOKEN_INVALID` if not found
6. If `isRevoked === true`: **family compromise** — call `RefreshTokenRepository.revokeFamilyByUserId(userId, family)`; return `TOKEN_REUSE_DETECTED` (401)
7. Mark old token revoked: `RefreshTokenRepository.revokeToken(id)`; set `replacedByHash` to new token's hash
8. Generate new access token + new refresh token (same `family`)
9. Store new refresh token hash in DB
10. Return new access token in body; set new refresh token cookie

### 7.4 Logout Flow

1. `POST /api/v1/auth/logout` — requires valid access token in `Authorization` header
2. Extract raw refresh token from `req.cookies.refreshToken`
3. Hash it and call `RefreshTokenRepository.revokeToken()` for that hash
4. Clear cookie: `res.clearCookie('refreshToken')`
5. Call `AuditEventRepository.create({ action: 'LOGOUT', ... })`
6. Return `200 { success: true, data: { message: 'Logged out successfully' } }`

### 7.5 Lockout Policy

- 5 failed consecutive login attempts → `lockoutUntil = now + 15 minutes`
- On lockout, respond with `ACCOUNT_LOCKED` (401) and include `remainingSeconds` in the error details
- Successful login resets `failedLoginAttempts = 0` and `lockoutUntil = NULL`
- Admin can manually unlock: `PATCH /api/v1/users/:id/unlock` — sets `failedLoginAttempts = 0`, `lockoutUntil = NULL`

### 7.6 Authorization Middleware

```
authenticate       → verifies access token; attaches req.user = { id, role, bankUserId, mustChangePassword }
authorize(roles)   → checks req.user.role is in the allowed roles array; returns 403 FORBIDDEN if not
```

After `authenticate` runs and `mustChangePassword === true`, block all routes except `PATCH /api/v1/profile/password` with `403 MUST_CHANGE_PASSWORD`. This check lives inside `authenticate.js`, not in individual route handlers.

**Role permission matrix:**

|---|---|---|---|

## 9. Core Banking Rules

### 9.1 Credit

1. Hash `accountNumber` param → look up account by `accountNumberHash`
2. If not found → `ACCOUNT_NOT_FOUND` (404)
3. If `accountStatus !== 'active'` → `ACCOUNT_FROZEN` (403)
4. Validate `amount > 0` and max 2 decimal places (Zod layer)
5. Inside `BaseRepository.withTransaction(async (t) => { ... })` with `SERIALIZABLE` isolation:
   - `AccountRepository.creditBalance(accountId, amount, t)`
   - `TransactionRepository.create({ type: 'credit', toAccountId, amount, currency, initiatedBy, balanceAfter: account.balance + amount, status: 'completed' }, { transaction: t })`
6. Create `credit` notification for account owner
7. Write `CREDIT` audit event

### 9.2 Debit

1. Look up account by `accountNumberHash`
2. If not found → `ACCOUNT_NOT_FOUND` (404)
3. If `account.userId !== req.user.id` → `ACCOUNT_NOT_OWNED` (403) — applies to all roles including admin and employee
4. If `accountStatus !== 'active'` → `ACCOUNT_FROZEN` (403)
5. If `account.balance - amount < 0` → `INSUFFICIENT_FUNDS` (400) — check before opening transaction
6. Inside `withTransaction`:
   - `AccountRepository.debitBalance(accountId, amount, t)` — SQL: `UPDATE accounts SET balance = balance - ? WHERE id = ? AND balance >= ?`
   - If 0 rows affected (race condition): throw `INSUFFICIENT_FUNDS`
   - `TransactionRepository.create({ type: 'debit', fromAccountId, amount, currency, initiatedBy, balanceAfter: account.balance - amount, status: 'completed' }, { transaction: t })`
7. Create `debit` notification
8. Write `DEBIT` audit event

### 9.3 Transfer

1. Look up both accounts by `accountNumberHash`
2. If either not found → `ACCOUNT_NOT_FOUND` (404)
3. If `sourceAccountNumber === destinationAccountNumber` → `SAME_ACCOUNT` (400)
4. If `fromAccount.userId !== req.user.id` → `ACCOUNT_NOT_OWNED` (403) — applies to all roles including admin and employee. Destination account has no ownership check — anyone can receive money
5. If either `accountStatus !== 'active'` → `ACCOUNT_FROZEN` (403)
6. If `fromAccount.currency !== toAccount.currency` → `CURRENCY_MISMATCH` (400)
7. If `fromAccount.balance - amount < 0` → `INSUFFICIENT_FUNDS` (400)
8. Inside `withTransaction`:
   - `AccountRepository.debitBalance(fromAccountId, amount, t)` with `AND balance >= ?` guard
   - If 0 rows affected: throw `INSUFFICIENT_FUNDS`
   - `AccountRepository.creditBalance(toAccountId, amount, t)`
   - `TransactionRepository.create({ type: 'transfer', fromAccountId, toAccountId, amount, currency, initiatedBy, balanceAfter: fromAccount.balance - amount, status: 'completed' }, { transaction: t })`
9. Create `transfer` notification for sender
10. Create `transfer` notification for receiver
11. Write `TRANSFER` audit event

### 9.4 Atomicity Rule

All balance mutations use Sequelize managed transactions via `BaseRepository.withTransaction()`. The isolation level is `SERIALIZABLE` for all `withTransaction` calls. This is configured once in `BaseRepository`:

```js
async withTransaction(callback) {
  return this.sequelize.transaction(
    { isolationLevel: Sequelize.Transaction.ISOLATION_LEVELS.SERIALIZABLE },
    callback
  );
}
```

If `callback` throws, Sequelize automatically rolls back the transaction. Never mutate balances outside a `withTransaction` call.

### 9.5 Amount Precision

- Zod: `z.number().positive().multipleOf(0.01)` — rejects 0, negatives, and more than 2 decimal places
- Stored as `DECIMAL(15,2)` — MySQL enforces 2 decimal precision at the DB level
- Returned as JS `Number` — guaranteed by `decimalNumbers: true` in Sequelize config

## 10. Encryption & Hashing

### 10.1 Encrypted Fields (AES-256-GCM)

| Table | Plain field | Stored column |
|---|---|---|
| users | nationalId | `nationalIdEncrypted` |
| users | phone | `phoneEncrypted` |
| accounts | accountNumber | `accountNumberEncrypted` |

Encrypted value format: `iv:authTag:ciphertext` (all hex-encoded, colon-separated string). Implemented in `src/utils/encryption.js`:

```js
encrypt(plaintext)  → 'ivHex:authTagHex:ciphertextHex'
decrypt(stored)     → plaintext string
hmacHash(value)     → 64-char hex string (deterministic HMAC-SHA256, keyed with ENCRYPTION_KEY)
```

### 10.2 HMAC-SHA256 Hash for Lookup

Encrypted values use a random IV per call — they are non-deterministic. A deterministic HMAC-SHA256 hash (keyed with `ENCRYPTION_KEY`) is stored alongside each encrypted field for equality lookups:

| Encrypted column | Hash column |
|---|---|
| `nationalIdEncrypted` | `nationalIdHash` |
| `phoneEncrypted` | `phoneHash` |
| `accountNumberEncrypted` | `accountNumberHash` |

Lookup rule: always call `hmacHash(input)` first, then pass the hash to the repository method. Never query by encrypted value.

### 10.3 Password Hashing

- Library: `argon2` (argon2id variant, default recommended params)
- Never store, log, or transmit plaintext passwords
- Hash on user creation and on password change
- Verify with `argon2.verify(storedHash, incomingPlaintext)`

### 10.4 Refresh Token Hashing

- Raw refresh token JWTs are hashed with SHA-256 using `tokenHelpers.hashToken(raw)` before being written to MySQL
- Only the hash (`tokenHash`) is stored; raw tokens are never persisted to the DB or written to logs

### 13.2 Validation Error Shape
```json
{

    "code": "VALIDATION_ERROR",

  }

```

### 13.3 Error Code Registry

| Code | HTTP Status | Meaning |
|---|---|---|
| `VALIDATION_ERROR` | 400 | Zod schema failure — includes `details` array |
| `INVALID_CREDENTIALS` | 401 | Wrong bankUserId or password |
| `ACCOUNT_LOCKED` | 401 | Too many failed login attempts — includes `remainingSeconds` in `error.details` |
| `ACCOUNT_INACTIVE` | 400 | User account is deactivated (`isActive: false`) |
| `ACCOUNT_FROZEN` | 403 | Bank account status is not `'active'` |
| `ACCOUNT_NOT_OWNED` | 403 | The source account does not belong to the logged-in user |
| `TOKEN_EXPIRED` | 401 | JWT access or refresh token has expired |
| `TOKEN_INVALID` | 401 | JWT is malformed or signature mismatch |
| `TOKEN_REUSE_DETECTED` | 401 | Refresh token family compromise detected |
| `MUST_CHANGE_PASSWORD` | 403 | Temporary password must be changed before accessing this endpoint |
| `FORBIDDEN` | 403 | Valid token but insufficient role |
| `USER_NOT_FOUND` | 404 | No user with given id or bankUserId |
| `ACCOUNT_NOT_FOUND` | 404 | No account with given number |
| `EMAIL_EXISTS` | 409 | Email already registered |
| `NATIONAL_ID_EXISTS` | 409 | National ID already registered |
| `INSUFFICIENT_FUNDS` | 400 | Balance would go negative |
| `CURRENCY_MISMATCH` | 400 | Transfer between accounts of different currencies |
| `SAME_ACCOUNT` | 400 | Transfer source and destination are the same account |
| `CANNOT_DELETE_ADMIN` | 409 | Attempt to delete the last admin account |
| `INVALID_CURRENT_PASSWORD` | 401 | Wrong current password on password change |
| `INTERNAL_ERROR` | 500 | Unexpected server error |

### 13.4 Global Error Handler

A single `errorHandler` middleware is the last middleware registered in `app.js`. It catches all errors passed via `next(err)`. Unhandled promise rejections and uncaught exceptions are caught at the process level, logged via pino, and trigger graceful shutdown (close DB connection, then `process.exit(1)`).

Sequelize-specific errors must be caught and mapped:
- `SequelizeUniqueConstraintError` → map to `EMAIL_EXISTS` or `NATIONAL_ID_EXISTS` based on the constraint field name
- `SequelizeForeignKeyConstraintError` → map to `INTERNAL_ERROR` with a descriptive log (should not reach the client)
- `SequelizeConnectionError` → map to `INTERNAL_ERROR`, log as fatal

### 15.3 Database Rules
- Never call `sequelize.sync({ force: true })` or `sequelize.sync({ alter: true })` — use `{ force: false, alter: false }` only
- Never import a Sequelize model outside of `src/repositories/`
- Always pass the Sequelize `transaction` object to every repository call inside `withTransaction` — missing it is a silent bug
- All `withTransaction` calls use `SERIALIZABLE` isolation — never override this
- Never store monetary values as `FLOAT` or `DOUBLE` — only `DECIMAL(15,2)`
- The `debitBalance` SQL must include `AND balance >= ?` guard — never just `SET balance = balance - ?`

### 15.4 Security Rules
- Never log passwords, raw JWT tokens, raw nationalId, raw phone numbers, or raw account numbers
- Never store plaintext passwords — always argon2id hash
- Never store raw refresh tokens — always SHA-256 hash before persisting
- Always encrypt nationalId, phone, and accountNumber with AES-GCM before storing
- Always store HMAC-SHA256 hash alongside encrypted fields for lookup
- Never expose internal DB ids in error messages
- Swagger UI must be unreachable in production (`NODE_ENV === 'production'`)

### 15.5 Code Quality Rules
- Every async route handler and service method must be wrapped in try/catch and call `next(err)` on error — no unhandled promise rejections
- Every response must use the `{ success, data }` or `{ success, error }` envelope — no exceptions except the health endpoint
- Zod validation middleware must run before any controller logic for every route that accepts a body
- `authenticate` middleware must run before `authorize` on all protected routes
- `mustChangePassword` check must live in `authenticate.js` — not in individual controllers
